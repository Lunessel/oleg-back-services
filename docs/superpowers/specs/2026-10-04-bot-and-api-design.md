# Telegram-бот і API для лендінгу вантажних перевезень — дизайн

Дата: 2026-10-04

## Мета

Бекенд для сайту `oleg-webapp`:

1. Заявки з сайту потрапляють у Telegram-канал через бота.
2. Користувач може залишити заявку прямо в боті; вона йде в той самий канал.
3. Адміни (Telegram id з env) керують у боті контентом сайту: видами вантажних перевезень і значеннями тарифів.
4. Сайт отримує цей контент через HTTP API.

## Архітектура

Один репозиторій, один Python-пакет `app` зі спільним шаром БД і бізнес-логіки. З нього запускаються два процеси:

- `api` — FastAPI (uvicorn);
- `bot` — aiogram 3, long polling.

`docker compose` піднімає три сервіси: `db` (Postgres 16), `api`, `bot`. `api` і `bot` збираються з одного образу й відрізняються командою запуску. Обидва монтують volume `media`; `db` має власний volume з даними.

Бот не ходить в API по HTTP: обидва процеси викликають функції з `app/services` напряму.

### Стек

Python 3.12, aiogram 3, FastAPI, SQLAlchemy 2 (async) + asyncpg, Alembic, pydantic-settings, pytest + pytest-asyncio + httpx, pip (`requirements.txt`).

### Змінні середовища

| Змінна | Призначення |
|---|---|
| `BOT_TOKEN` | токен бота |
| `LEADS_CHAT_ID` | id каналу для заявок (бот має бути адміном каналу) |
| `ADMIN_IDS` | Telegram id адмінів через кому |
| `DATABASE_URL` | `postgresql+asyncpg://...` |
| `API_KEY` | секрет для `POST /api/leads` |
| `PUBLIC_BASE_URL` | публічна адреса API, з неї будуються URL фото |
| `MEDIA_DIR` | каталог фото (за замовчуванням `media`; у docker compose — `/app/media`) |
| `CONTACT_PHONE` | телефон, який бот показує, якщо заявку не вдалося надіслати |
| `TZ` | часовий пояс для дат у боті (за замовчуванням `Europe/Kyiv`) |

## Дані

### `services` — види перевезень

| Поле | Тип | Примітка |
|---|---|---|
| `id` | int PK | |
| `title` | text | |
| `items` | JSON | масив рядків (пункти під заголовком), щонайменше один |
| `image` | text | повний URL або шлях відносно `MEDIA_DIR` (`services/<uuid>.jpg`) |
| `position` | int | порядок на сайті, за зростанням |

### `tariff_rows` — рядки тарифів

| Поле | Тип | Примітка |
|---|---|---|
| `key` | text PK | напр. `city.min_order` |
| `card` | text | `city`, `intercity` або `loaders` |
| `label` | text | статичний «ключ», з бота не змінюється |
| `value` | text | єдине поле, яке редагує адмін |
| `position` | int | порядок усередині картки |

Назви й порядок трьох карток задані константою в `services/tariffs.py`: `city` — «По місту», `intercity` — «За місто / по Україні», `loaders` — «Послуги вантажників».

### `leads` — заявки

| Поле | Тип | Примітка |
|---|---|---|
| `id` | int PK | |
| `source` | text | `hero`, `calculator`, `callback`, `services_consult`, `bot` |
| `name` | text, nullable | у `hero` імені немає |
| `phone` | text | |
| `payload` | JSON | усі поля заявки як є |
| `created_at` | timestamptz | |
| `sent_at` | timestamptz, nullable | час успішної доставки в канал |

### Початкові дані

Міграція засіває 5 послуг і 6 рядків тарифів із поточного `oleg-webapp/data/content.ts`. Фото засіяних послуг — наявні unsplash-URL.

## API

Усі відповіді — JSON.

### `GET /api/services`

```json
[{ "id": 1, "title": "…", "items": ["…", "…"], "image": "https://…" }]
```

Відсортовано за `position`. Якщо `image` — відносний шлях, API повертає `{PUBLIC_BASE_URL}/media/{image}`.

### `GET /api/pricing`

```json
{ "cards": [{ "id": "city", "title": "По місту", "rows": [{ "label": "…", "value": "…" }] }] }
```

Форма збігається з `pricing` у `content.ts`.

### `POST /api/leads`

Заголовок `X-API-Key`; без нього або з неправильним — 401. Тіло — заявка у форматі сайту, дискримінована полем `source`:

- `hero`: `from`, `to`, `phone`
- `calculator`: `name`, `phone`, `serviceType`, `vanSize`, `loaders`, `route`
- `callback`, `services_consult`: `name`, `phone`

Невалідне тіло — 422. Порядок дій: записати заявку в `leads` → надіслати в канал → проставити `sent_at` → відповісти `201 {"ok": true}`.

Якщо Telegram повернув помилку, заявка лишається в базі з `sent_at = NULL`, API відповідає 502. Автоматичного повторного надсилання немає.

### Інше

- `GET /media/*` — статика з `MEDIA_DIR`.
- `GET /health` → `{"status": "ok"}`.
- CORS не потрібен: до API звертається лише сервер Next.js.

## Формат повідомлень у каналі

HTML-розмітка, значення користувача екрануються.

Заявки з сайту — як у поточному `lib/telegram.ts`: жирний заголовок за джерелом («Заявка з головної форми», «Заявка з калькулятора вартості», «Замовлення дзвінка», «Консультація щодо вантажу»), далі рядки `Поле: значення` з тими самими підписами й мапами значень (`small` → «Малий» тощо).

Заявка з бота:

```
<b>Заявка з Telegram-бота</b>
Ім'я: …
Послуга: …
Вантажники: Ні | Так, кількість — N
Звідки: …
Куди: …
Дата: дд-мм-рррр
Час: гг:00
Телефон: …
Telegram: @username (якщо є)
```

## Бот

### Користувач

`/start` показує привітання й клавіатуру: «Залишити заявку», а для адмінів ще й «Адмін-панель».

Сценарій заявки (FSM):

1. Ім'я.
2. Послуга — кнопки з назвами з `services`. Якщо таблиця порожня, крок пропускається, у заявці «Послуга: не вказано».
3. Чи потрібні вантажники — «Так» / «Ні».
4. Кількість вантажників (лише після «Так») — ціле число більше нуля.
5. Звідки.
6. Куди.
7. Дата — кнопки на 7 днів від сьогодні.
8. Час — кнопки 8:00–20:00.
9. Телефон — кнопка «Надіслати номер телефону» або текст. Номер нормалізується й перевіряється за тим самим правилом, що на сайті: `+380XXXXXXXXX` або `0XXXXXXXXX`.

На кожному кроці є «Скасувати» (і команда `/cancel`), що скидає стан і повертає головне меню. Невалідне введення — повторне запитання того самого кроку.

Після телефону заявка зберігається в `leads` із `source = bot` і надсилається в канал тією самою функцією, що й заявки сайту. Користувач бачить «Дякуємо за замовлення! Ми зв'яжемося з вами найближчим часом.» Якщо надсилання в канал не вдалося, заявка лишається в базі, а користувач бачить прохання зателефонувати.

### Адмін

Фільтр `IsAdmin` перевіряє `from_user.id` за `ADMIN_IDS` і стоїть на всіх адмін-роутерах. Не-адмін кнопки не бачить, а його повідомлення й callback-и до адмін-хендлерів не доходять.

«Адмін-панель» → inline-меню: «Види перевезень», «Тарифи».

**Види перевезень**

- Список послуг за `position` + «Додати».
- Картка послуги: фото з підписом (назва й пункти) і кнопки «Фото», «Назва», «Пункти», «↑», «↓», «Видалити», «Назад».
- Додавання: фото → назва → пункти. Пункти вводяться одним повідомленням, кожен непорожній рядок — окремий пункт. Нова послуга стає останньою.
- «Фото», «Назва», «Пункти» змінюють одне відповідне поле.
- «↑» / «↓» міняють послугу місцями із сусідньою; на краях списку нічого не роблять.
- «Видалити» питає підтвердження.

**Тарифи**

- Три картки → рядки картки у вигляді `label: value` → вибір рядка → бот просить нове значення → зберігає й показує оновлену картку.
- Додавати, видаляти рядки чи змінювати `label` не можна.

### Фото

Бот бере найбільший розмір фото з повідомлення, завантажує його в `MEDIA_DIR/services/<uuid>.jpg` і пише відносний шлях у `services.image`. При заміні фото чи видаленні послуги попередній локальний файл видаляється; URL-зображення (засіяні) просто перезаписуються.

### Стан

FSM — `MemoryStorage`. Незавершені діалоги губляться при рестарті бота; це прийнятно.

## Зміни в `oleg-webapp`

- `lib/telegram.ts` видаляється. Додається `lib/backend.ts` з функціями `sendLead`, `getServices`, `getPricing`.
- `app/api/lead/route.ts`: валідація й rate limit без змін, далі `sendLead` → `POST {BACKEND_URL}/api/leads` із `X-API-Key`. Помилка бекенду → та сама відповідь 502, що й зараз.
- Блоки послуг і тарифів отримують дані з `getServices` / `getPricing` (`fetch` із `next: { revalidate: 60 }`). При помилці чи порожній відповіді — fallback на значення з `data/content.ts`.
- `next.config.mjs`: хост бекенду в `images.remotePatterns`.
- `.env.example`: `BACKEND_URL`, `BACKEND_API_KEY` замість `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.

Зміни в `oleg-webapp` не комітяться в межах цієї роботи.

## Тести

pytest на окремій тестовій базі Postgres (той самий контейнер `db`), надсилання в Telegram замокане:

- `services/leads`: форматування кожного джерела, екранування HTML, `sent_at` при успіху й при помилці надсилання.
- `services/catalog`: створення, оновлення полів, видалення, перестановка, поведінка на краях списку.
- `services/tariffs`: групування в картки, оновлення значення, невідомий ключ.
- API: `GET /api/services`, `GET /api/pricing`, `POST /api/leads` (201, 401, 422, 502), побудова URL фото.
- Нормалізація й перевірка телефону.

Хендлери бота перевіряються вручну на реальному боті.
